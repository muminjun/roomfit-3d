# Editor bundle and 3D chunk investigation

`src/components/editor2d/konva.ts` imports React Konva Core and explicitly registers the four used Konva shapes (`Line`, `Text`, `Rect`, `Circle`); it exports those plus `Stage`, `Layer`, and `Group`. The installed shape modules register themselves with Konva, and the full `react-konva` entry imports all of `konva`. Both editor files now use the adapter. Existing `KonvaEventObject` imports are type-only. No dependencies, overrides, or warning limits were changed.

After the editor switch, `npm run build` passed with **646.28 kB** main JS (200.47 kB gzip) and **938.40 kB** lazy viewer JS (248.85 kB gzip). The earlier S3 main asset was 702.50 kB (216.24 kB gzip), so the observed main difference is −56.22 kB (−15.77 kB gzip). S4 code and other files changed between builds, so this is not an isolated measurement of the adapter alone. Both chunks remain above Vite's 500 kB warning. Browser shape and interaction tests are needed to confirm all registrations.

Local Vite 8 and Rolldown types support `build.rolldownOptions.output.codeSplitting.groups`, including `name`, `test`, `priority`, and `includeDependenciesRecursively`. A possible later experiment is a narrowly matched group for `node_modules[\\/]three[\\/]build[\\/]three.core.js`, e.g. `groups: [{ name: 'three-core', test: /node_modules[\\/]three[\\/]build[\\/]three\.core\.js$/, includeDependenciesRecursively: false }]`. This groups a module; it does not shrink it, and its unminified file is 1.4 MiB. Extracting it may merely move the warning and may alter requests, caching or lazy loading. Measure emitted sizes and check network, 2D initial loading, 3D behavior and both browsers in an isolated build before adopting any configuration. No Vite config was edited.

## S5 grouping experiment

One isolated build to `/tmp/roomfit-bundle-experiment-s5-20261103` grouped React, Konva, and the existing Three.js core and module entry points. All minified chunks were below 500 kB: application 164.82 kB, Konva 133.03 kB, React 347.58 kB, lazy viewer 195.48 kB, Three module 365.22 kB, Three core 383.44 kB, and Rolldown runtime 0.72 kB. No size threshold or dependencies were changed, and the experiment did not write `dist`. This is a transfer and caching split, not a reduction in total JavaScript; runtime and lazy loading require browser verification against the final subpath build.

`check:dist` now inspects index `src`/`href` references including favicon, plus generated JS imports, dynamic imports and Vite preload-map asset literals, ensuring each local reference resolves within the configured base and exists. Temporary fixture checks passed for a valid subpath and rejected a missing dynamic chunk, root-relative asset leak, and missing favicon. `test:e2e:subpath` invokes the separate Playwright configuration without rebuilding the final output.
