## Spec compliance

The main structure follows the additive design: optional v2 fields, strict nested schemas and globally unique IDs, architecture edits through the existing commit/history path, derived placement/operation warnings, valid-final-placement move/resize, and intentionally permissive rotation. Architecture numeric forms, zones, an expanded catalog, 2D overlays, and real 3D wall voids are present. Old v2 objects can omit the new fields, and serialization preserves their omission. Rotation's relaxed placement policy is intentional under the latest design and is not a review defect.

Full compliance cannot yet be asserted. The confirmed defects below break physical wall ownership, agreement between collision and rendered walls, accepted JSON normalization, and the supported architecture capacities. The original AC report remains pending for broad browser/platform coverage, which is appropriate until the coordinator completes validation. Independent connected rooms/floors remain deferred as the design explicitly records; zones plus partitions should not be represented to the user as independently modeled rooms or verified building feasibility.

## Code quality

The domain command/schema separation and use of pure derived warnings are sound, and the new Three geometries have explicit disposal. The largest quality weakness is the architectural solid algorithm: it discards host ownership and builds a global Cartesian grid across every wall/opening boundary. That creates both a correctness defect and severe unnecessary geometry growth. The parser also normalizes polygon topology without adapting the newly dependent opening references. These are integration gaps across otherwise individually tested modules, not formatting/style concerns.

## Critical

None confirmed. The supported-capacity rendering failure below is classified Important because the viewer has an error boundary and this review did not establish committed-data loss.

## Important

### 1. Door/window cuts also erase unrelated intersecting walls

**Location:** `src/components/viewer3d/architecture.ts:71–73` (all cuts applied after the union); source attribution is discarded at lines 22–39.

**Repro:** In a 4000×3000×2400 room, create horizontal partition `host` from (0,1500) to (4000,1500), and vertical partition `cross` from (1400,500) to (1400,2500), both thickness 100 and height 2400. Add a door to `host`, offset 1000, width 800, height 2000, sill 0. The model validates with zero architecture issues. A ray from `[1.2,1,1.5]` in direction `[1,0,0]`, maximum distance 0.4m, gets zero wall hits: the host door has also cut the crossing partition. Collision still retains the entire cross-partition rect `[1350,500,1450,2500]`.

**Impact:** The user sees a physically nonexistent passage and 2D/collision/3D disagree. Openings belong to one host and must remove material from that host before the remaining sources are unioned.

**Test gap:** Existing architecture ray tests cover isolated exterior/partition openings and ordinary joins, not an opening overlapping a different wall source. Add crossing/T-junction ownership ray tests and verify the unaffected source stays solid.

### 2. Valid supported architecture capacities cause explosive tessellation and a renderer exception

**Location:** `src/components/viewer3d/architecture.ts:41–49`, `:58–81`, `:104–106`.

**Repro:** `/tmp/roomfit-architecture-stress.json` contains 64 partitions and 100 windows, within the declared schema limits. `projectSchema.safeParse` succeeds and `validateArchitecture` returns no issues. Loading it and calling `buildArchitecturalWallGeometry(project.room)` through Vite SSR failed in this environment with `RangeError: Invalid array length` at the `positions.push` in `quad`. A simpler valid 64-partition/no-opening probe already emitted **2,174,748 vertices**, taking approximately **571ms** in Node, before a browser uploaded or rendered any geometry.

The fixture uses a 30000×30000×5000 room. For partition index `i=0..63`: start `(100+3i,200+450i)`, end `(29000−7i,200+450i)`, thickness `100+3i`, height `4800−11i`. For window index `i=0..99`: host `wall(i%64)`, offset `300+127i`, width `400+i`, height `600+13i`, sill `300+17i`. All IDs are unique.

**Impact:** A permitted imported or interactively authored plan can freeze the main thread, consume excessive memory, or lose the 3D view. The global x×height×z subdivision also repeats scans over all source solids/cuts for every cell and neighbor. Retain the supported limits while replacing or bounding this tessellation; local surface subdivision, source-aware clipping, and coplanar merging are possible directions.

**Test gap:** Performance tests cover the old exterior-wall/furniture workload, not maximum architecture counts with distinct offsets, sill heights, partition heights and coordinates. Add a bounded-time/geometry-size architecture stress test plus successful rendering under the declared capacities.

### 3. Accepted counterclockwise JSON silently moves openings to a different wall

**Location:** `src/features/project/json.ts:145` (normalized polygon substituted while `room.openings` remains unchanged); `src/features/architecture/geometry.ts:16–18` interprets the host as the outgoing edge.

**Repro:** `/tmp/roomfit-architecture-ccw.json` has polygon `a(0,0), b(0,3000), c(4000,3000), d(4000,0)` and a door with host `a`, offset 1000, width 800. Before import the door segment is `(0,1000)`→`(0,1800)` on the left wall. `parseProjectJson` returns success and an orientation-normalization message, zero warnings, but the resulting door segment is `(1000,0)`→`(1800,0)` on the top wall.

**Impact:** The original accepted-CCW import behavior now silently changes expanded project geometry. Preserving vertex IDs does not preserve an outgoing-edge reference after reversal. Remap exterior host IDs, offsets, hinge and swing semantics through reversal/collinear normalization so the same world opening and leaf are retained; preserve partition-hosted openings.

**Test gap:** Existing CCW normalization coverage predates openings, and expanded JSON roundtrips use already normalized polygons. Add CCW and collinear-point normalization cases with exterior openings and compare world endpoints and physical hinge/swing after import.

### 4. Invalid retained openings remove collision even when 3D renders a solid wall

**Location:** `src/features/architecture/geometry.ts:50–51`; compare `src/components/viewer3d/architecture.ts:34–39`.

**Repro:** Start with a 2400mm-high partition and a 2100mm door, then reduce the partition height to 1800mm. Retaining the opening with `OPENING_HEIGHT` is intentional. For the resulting 4000mm horizontal partition at y1500 with a door offset1000/width800, a box centered at (1400,1500), 400×400×1000mm, passes `validatePlacement` with zero issues. `getPartitionSolidRects` removes the doorway span. However, the 3D builder rejects the invalid opening cut: a ray through that box location gets two wall hits.

**Impact:** Numeric placement can commit furniture inside a wall displayed as solid. This also occurs when a partition is shortened so the retained opening exceeds its host length. Use a consistent policy for physical cuts in collision and rendering while retaining the derived diagnostic; an invalid opening should not silently create a valid passage in only one subsystem.

**Test gap:** No test compares placement and raycast results after a previously valid hosted opening becomes invalid through host/room edits. Add height and width invalidation cases, including Undo restoration.
