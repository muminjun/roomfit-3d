# Furniture command report

Furniture commands use the shared placement validator before committing additions, movement, resize, rotation, duplication, and reset. Name, palette color and deletion remain available for existing invalid placements. A valid geometry edit can recover such an item. All commits preserve the other furniture and room data; same-key movement participates in store coalescing. Furniture count is limited to 100.

`createFurnitureCandidate` accepts an explicit ID for deterministic previews (otherwise it uses the canonical ID generator). `findValidPlacement` searches up to 1000 offsets at 100mm increments in squared-distance order, with y then x tie-breaking, and returns null when none qualify. Click addition starts at the room bounding-box center; duplication starts at the original center. `resizeFromCorner` fixes the opposite world corner and rounds world dimensions before deriving the center and local dimensions. The caller must validate its returned candidate.

The tests were written before implementation; the initial run failed because the new command module did not exist. The focused suite now passes 12 tests covering touching/overlap, concavity, half-mm and odd width snapping, rotation, resize anchoring, invalid placement recovery, height, reset, non-geometric edits, duplication, the search limit, 100-item limit, and coalescing. A full suite run before the final additional search-limit test passed 59 tests; `npm run lint` and `npm run typecheck` also passed. Browser interactions remain a separate integration gate.

Search-origin regression: a fractional viewport center previously caused every candidate to fail half-millimeter validation. A new test first failed with `null` for `(2100.123,1700.377)`; automatic search now rounds the origin to `(2100,1700.5)` and rejects nonfinite inputs immediately. Explicit add/move coordinates remain subject to strict validation. After the fix, the full suite passed 65 tests; lint and typecheck passed.
